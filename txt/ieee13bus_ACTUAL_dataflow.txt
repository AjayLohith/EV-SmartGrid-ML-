LOCATION OF V-I MEASUREMENT:
----------------------------

    BUS3 ──► [RL Branch] ──► BUS6 ──► [Transformer] ──► BUS7-----subsystem
                                                          │
                                                    [V-I Measurement]

                                                    [Power Block]
                                                       P    Q
                                                       │    │
                                                       ▼    ▼

WHY BUS7?
---------

Reason 1: END-USER LOCATION
    - Bus7 is AFTER a step-down transformer
    - Represents actual EV charging station voltage level
    - Where customers connect their EVs

Reason 2: DOWNSTREAM OF MAIN HUB
    - Path: Source → Bus1 → Bus3 → Bus6 → Bus7
    - Any attack upstream will propagate here
    - Captures cumulative grid effects

Reason 3: ISOLATED MEASUREMENT POINT
    - Transformer isolates Bus7 from Bus6
    - Clean measurement without upstream noise
    - Represents single customer/station

Reason 4: REPRESENTATIVE SAMPLE
    - Similar structure at Bus8, Bus12, Bus13
    - ML model trained on Bus7 can generalize
    - One measurement point is sufficient for detection

SECTION 6: CAPACITOR LOAD (C ONLY) - POWER FACTOR CORRECTION
================================================================================

WHY ONLY CAPACITOR AT BUS3?
---------------------------

    ┌─────────────────────────────────────────────────────────────────────────┐
    │                                                                         │
    │   PROBLEM: EV CHARGERS ARE INDUCTIVE                                   │
    │   ────────────────────────────────                                     │
    │                                                                         │
    │   EV chargers contain:                                                 │
    │   - Transformers (inductors)                                           │
    │   - Rectifier coils (inductors)                                        │
    │   - Filter inductors                                                   │
    │                                                                         │
    │   Inductors CONSUME reactive power (Q)                                 │
    │   This causes LAGGING power factor (0.7-0.85)                         │
    │                                                                         │
    │   Result:                                                              │
    │   - Grid must supply extra current                                     │
    │   - More losses in transmission lines                                  │
    │   - Voltage drops                                                      │
    │                                                                         │
    ├─────────────────────────────────────────────────────────────────────────┤
    │                                                                         │
    │   SOLUTION: CAPACITOR BANK AT BUS3                                     │
    │   ───────────────────────────────                                      │
    │                                                                         │
    │   Capacitors GENERATE reactive power (Q)                               │
    │                                                                         │
    │   Placement at Bus3:                                                   │
    │   - Central location (main hub)                                        │
    │   - Compensates for ALL downstream loads                               │
    │   - Most efficient placement                                           │
    │                                                                         │
    │   Result:                                                              │
    │   - Power factor improves to 0.95-0.99                                 │
    │   - Less current from sources                                          │
    │   - Reduced losses                                                     │
    │   - Better voltage regulation                                          │
    │                                                                         │
    └─────────────────────────────────────────────────────────────────────────┘


    WITHOUT CAPACITOR:                    WITH CAPACITOR:
    
    Source supplies:                      Source supplies:
    P = 100 kW                            P = 100 kW
    Q = 60 kVAR                           Q = 10 kVAR (capacitor provides 50)
    S = 116.6 kVA                         S = 100.5 kVA
    PF = 0.86 (poor)                      PF = 0.995 (excellent)
    I = High                              I = Lower (less losses)

SECTION 7: DATA FLOW FROM SIMULINK TO ML
================================================================================

STEP-BY-STEP PROCESS:
---------------------

1. POWER ON (Click RUN in Simulink)
   │
   ├── Source 1 generates 3-phase AC → flows through Bus1 → Bus3
   │
   └── Source 2 generates 3-phase AC → flows through Bus4 → Bus5 → Bus3

2. POWER DISTRIBUTION AT BUS3
   │
   ├── Branch to Bus6 → Bus7 (measurement point)
   ├── Branch to Bus9 → Bus10
   ├── Branch to Bus11 → Bus12, Bus13
   └── Capacitor load (power factor correction)

3. MEASUREMENT AT BUS7
   │
   ├── V-I Measurement Block captures Vabc, Iabc
   │
   └── Power Block calculates:
       │
       ├── P = Active Power
       └── Q = Reactive Power

4. TO WORKSPACE
   │
   ├── simout = [P(t=0), P(t=0.001), P(t=0.002), ...]
   │
   └── simout1 = [Q(t=0), Q(t=0.001), Q(t=0.002), ...]

5. EXPORT TO PYTHON
   │
   ├── Save as .mat: save('data.mat', 'simout', 'simout1')
   │
   └── Or save as .csv: csvwrite('data.csv', [simout, simout1])

6. ML MODEL TRAINING
   │
   ├── Load data in Python
   ├── Feature engineering (power factor, apparent power, etc.)
   ├── Train Logistic Regression and SVM
   └── Detect attacks based on P and Q anomalies

SECTION 12: HOW ATTACKS ARE SIMULATED FOR ML TRAINING
================================================================================

Since there are no hackable components in the Simulink model, attacks are
SIMULATED in the DATA itself (not in the model):


METHOD 1: Python Data Manipulation (Your Current Approach)
----------------------------------------------------------

    Step 1: Run normal Simulink simulation
            → Get normal P, Q values in simout/simout1
            
    Step 2: Export to CSV (data/simulink_data.csv)
    
    Step 3: Python script (generate_attack_data.py) adds:
            → False Data Injection: Add noise/bias to P, Q values
            → DoS Simulation: Set P=0, Q=0 for some samples
            → Scaling Attacks: Multiply P, Q by random factors
            
    Step 4: Save as attack_dataset.csv
    
    Step 5: Train ML model to distinguish normal vs attack


METHOD 2: Simulink Signal Injection (Alternative)
-------------------------------------------------

    You can add injection blocks in Simulink:
    
    [V-I Measurement] → [+ Sum Block] → [Power Box]
                              ▲
                              │
                        [Attack Signal]
                        (Step, Random, etc.)
    
    This simulates what happens when SCADA is compromised in real world.

SECTION 13: ATTACK SCENARIOS (What SCADA Attacks Look Like)
================================================================================

In REAL PRODUCTION, when SCADA is compromised, these attacks affect P, Q values:


ATTACK TYPE 1: FALSE DATA INJECTION (FDI)
-----------------------------------------

    Real World:  Attacker hacks SCADA RTU, sends fake V, I readings
    
    Effect:      P, Q values are WRONG (too high or too low)
    
    Simulation:  In Python, add bias: P_attack = P_normal + random_noise
    
    Example:
    Normal:     P = 85 kW,  Q = 32 kVAR
    Attack:     P = 145 kW, Q = 58 kVAR  ← ML detects abnormal values


ATTACK TYPE 2: DENIAL OF SERVICE (DoS)
--------------------------------------

    Real World:  Attacker floods SCADA network, blocks communication
    
    Effect:      P, Q values drop to ZERO or show errors
    
    Simulation:  In Python, set: P_attack = 0, Q_attack = 0
    
    Example:
    Normal:     P = 85 kW,  Q = 32 kVAR
    Attack:     P = 0 kW,   Q = 0 kVAR   ← ML detects sudden drop


ATTACK TYPE 3: REPLAY ATTACK
----------------------------

    Real World:  Attacker records old data, replays it during attack
    
    Effect:      P, Q show OLD values (look normal but are stale)
    
    Simulation:  In Python, repeat old rows in dataset
    
    Example:
    Normal (t=10):  P = 85 kW
    Normal (t=20):  P = 90 kW
    Attack (t=20):  P = 85 kW  ← Replayed old value (harder to detect)


ATTACK TYPE 4: SCALING ATTACK
-----------------------------

    Real World:  Attacker modifies SCADA calibration factors
    
    Effect:      P, Q values are scaled by wrong factor
    
    Simulation:  In Python, multiply: P_attack = P_normal * 1.3
    
    Example:
    Normal:     P = 85 kW,  Q = 32 kVAR
    Attack:     P = 110 kW, Q = 42 kVAR  ← Scaled by 1.3
