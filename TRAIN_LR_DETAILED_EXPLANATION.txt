PART 1: OVERVIEW & PURPOSE
================================================================================

WHAT DOES THIS FILE DO?
-----------------------
The train_lr.py file trains a Logistic Regression (LR) model that predicts
grid stability. In plain English:

  "Is this power grid reading normal or abnormal?"
  
  Input: [voltage=0.98, current=80, power=500, ...]
  Process: Feed through LR model
  Output: "STABLE" (probability 0.95) or "UNSTABLE" (probability 0.05)

WHY LOGISTIC REGRESSION?
------------------------
Logistic Regression is chosen because:
1. FAST: Makes predictions in milliseconds
2. INTERPRETABLE: We can see which features matter most
3. PROBABILISTIC: Gives confidence scores (not just yes/no)
4. LINEAR BOUNDARY: Works well for grid stability (mostly linear relationships)

ANALOGY: Security Guard Decision
---------------------------------
A security guard decides entry. Each feature (ID, badge, time, dress) gets a
"score" in their head:
  ID expired?        → -10 points
  Valid badge?       → +30 points
  During work hours?  → +20 points
  Professional dress? → +15 points
  TOTAL: +55 points → ALLOWED (>threshold)

Logistic Regression does this mathematically for power grids!

PART 4: FUNCTION 1 - train_logistic_regression()
================================================================================

SIGNATURE:
----------
def train_logistic_regression(X_train, y_train, optimize=False):
    """Train a Logistic Regression model"""

INPUTS:
-------
  X_train: shape (4000, 13) – scaled training features
  y_train: shape (4000,)    – training labels (0 or 1)
  optimize: bool            – whether to tune hyperparameters

OUTPUTS:
--------
  LogisticRegression object (trained model ready to predict)

CODE WALKTHROUGH:
==================

IF optimize=False (default - use this):
--------------------------------------

  lr = LogisticRegression(
      C=1.0,
      penalty='l2',
      solver='lbfgs',
      max_iter=1000,
      random_state=42
  )
  lr.fit(X_train, y_train)
  return lr

HYPERPARAMETER EXPLANATION:

1. C = 1.0
   --------
   Controls regularization strength
   Formula: Loss = (1/C) * Regularization + Classification Loss
   
   Small C (e.g., 0.01):  Strong regularization → simpler model, underfitting
   Large C (e.g., 100):   Weak regularization → complex model, overfitting
   C=1.0:                 Balanced (default, works well)
   
   ANALOGY: Diet strictness
     C=0.01 = "No desserts EVER!" → too strict, starve creativity
     C=100  = "Eat whatever!" → too permissive, poor discipline
     C=1.0  = "Dessert on weekends" → balanced ✓

2. penalty = 'l2'
   ---------------
   Regularization type
   
   'l2': Ridge regularization
     Loss = Classification Loss + (λ * Σ(w²))
     Penalizes large weights
     Works with most solvers ✓
   
   'l1': Lasso regularization
     Loss = Classification Loss + (λ * Σ|w|)
     Forces some weights to zero
     Feature selection effect
   
   WHY 'l2'? Better stability and works with 'lbfgs' solver

3. solver = 'lbfgs'
   -----------------
   Algorithm to minimize loss function
   
   'lbfgs':
     • Best for small-medium datasets ✓ (4000 samples = good fit)
     • Convergence: Fast, reliable
     • Memory: Medium
     • Interactive with: LibLinear, SAGA
     
   Other options:
     • 'liblinear': Fast, for small datasets
     • 'saga': For sparse data
     • 'sag': Stochastic average gradient
   
   WHY 'lbfgs'? Standard choice for our dataset size

4. max_iter = 1000
   ----------------
   Maximum iterations for convergence
   
   Too low (e.g., 10):   Model doesn't converge → poor performance
   Too high (e.g., 10000):  Wastes computation time
   max_iter=1000: Usually converges within 50-200 iterations
   
   ANALOGY: Cooking time
     Too low: Food undercooked
     Too high: Wasted energy, food burns
     1000: Safe upper bound ✓

5. random_state = 42
   ------------------
   Seed for reproducibility
   
   If omitted: Different results each run (varied initialization)
   If set to 42: Same results every run ✓
   
   ANALOGY: Recipe with/without salt measurements
     No seed: "Add salt to taste" → varies
     With seed: "Add exactly 1 tsp salt" → consistent

.fit() METHOD:
==============

  lr.fit(X_train, y_train)

WHAT HAPPENS INTERNALLY:
  1. Initialize weights w = [w₁, w₂, ..., w₁₃]
  2. Forward pass: z = w·X + b
  3. Apply sigmoid: σ(z) = 1 / (1 + e^(-z))
  4. Compute loss: L = -[y·log(σ) + (1-y)·log(1-σ)]
  5. Backpropagation: Compute gradients ∇L
  6. Update weights: w_new = w_old - learning_rate × ∇L
  7. Repeat steps 2-6 until convergence or max_iter

TRAINING TIME: ~2 seconds for 4000 samples on CPU

---

IF optimize=True (hyperparameter tuning):
------------------------------------------

Code:
  param_grid = {
      'C': [0.001, 0.01, 0.1, 1, 10, 100],
      'penalty': ['l1', 'l2'],
      'solver': ['liblinear', 'saga'],
      'max_iter': [100, 500, 1000]
  }
  
  grid_search = GridSearchCV(
      lr, param_grid, cv=5, scoring='accuracy', n_jobs=-1, verbose=1
  )
  grid_search.fit(X_train, y_train)
  
  print(f"Best parameters: {grid_search.best_params_}")
  print(f"Best CV score: {grid_search.best_score_:.4f}")
  
  return grid_search.best_estimator_

WHAT IS GRID SEARCH?
====================
Exhaustively tries all parameter combinations:
  6 C values × 2 penalties × 2 solvers × 3 max_iters = 72 combinations!
  
For each combination:
  1. Train model on fold 1-4 (4/5 of data)
  2. Evaluate on fold 5
  3. Repeat 5 times (cross-validation)
  4. Average the scores
  5. Record best combination

EXAMPLE OUTPUT:
  Best parameters: {'C': 10, 'penalty': 'l2', 'solver': 'lbfgs', 'max_iter': 1000}
  Best CV score: 0.9825

COMPUTATION:
  72 combinations × 5 folds × 4000 training samples = SLOW!
  Runtime: ~10-15 minutes
  
  n_jobs=-1 = use all CPU cores for parallelization (faster)

WHEN TO USE optimize=True:
  • Want best possible performance
  • Have time for lengthy training
  • Tuning for production models

WHEN TO USE optimize=False:
  • Quick prototyping
  • Defaults work well enough
  • Our project uses these defaults ✓

RETURN VALUE:
=============
Trained LogisticRegression object with:
  • Fitted weights w
  • Intercept b
  • Ready to make predictions

def evaluate_model(model, X_test, y_test, model_name="Logistic Regression"):
    """Evaluate the trained model"""

INPUTS:
-------
  model: Trained LogisticRegression object
  X_test: shape (1000, 13) – test features
  y_test: shape (1000,)    – test labels
  model_name: str          – for display ("Logistic Regression")

OUTPUTS:
--------
  Dictionary with keys: [accuracy, precision, recall, f1, confusion_matrix]

CODE WALKTHROUGH:
==================

STEP 1: MAKE PREDICTIONS
  y_pred = model.predict(X_test)
  
  For each test sample:
    1. Compute sigmoid: σ = 1 / (1 + e^(-w·x - b))
    2. Apply threshold: if σ > 0.5 → predict 1, else predict 0
  
  OUTPUT: y_pred = [0, 1, 0, 0, 1, ...] (1000 predictions)

STEP 2: CALCULATE METRICS
  
  a) ACCURACY
  -----------
  Formula: Accuracy = (TP + TN) / (TP + TN + FP + FN)
  
  Code: accuracy = accuracy_score(y_test, y_pred)
  
  EXPLANATION:
    TP (True Positive):   Predicted 1, actually 1 ✓✓
    TN (True Negative):   Predicted 0, actually 0 ✓✓
    FP (False Positive):  Predicted 1, actually 0 ✗
    FN (False Negative):  Predicted 0, actually 1 ✗
  
  EXAMPLE (1000 test samples):
    TP = 495   (correct unstable predictions)
    TN = 475   (correct stable predictions)
    FP = 20    (false alarms - said unstable, was stable)
    FN = 10    (missed - said stable, was unstable)
    
    Accuracy = (495 + 475) / (495 + 475 + 20 + 10) = 970/1000 = 97.0%
  
  INTERPRETATION: "In 97 out of 100 cases, model was correct"
  
  ANALOGY: Weather forecast accuracy
    "Predicted rain 100 times, rain occurred 97 times" → 97% accuracy
  
  TYPICAL VALUE for our project: 98.20%

  b) PRECISION
  -----------
  Formula: Precision = TP / (TP + FP)
  
  Code: precision = precision_score(y_test, y_pred, average='weighted')
  
  EXPLANATION: Of all predictions of "UNSTABLE", how many were CORRECT?
  
  EXAMPLE:
    Model predicted UNSTABLE: 495 + 20 = 515 times
    Of these, actually UNSTABLE: 495 times
    Precision = 495 / 515 = 96.1%
  
  INTERPRETATION: "When model says UNSTABLE, it's correct 96.1% of the time"
  
  ANALOGY: Spam filter precision
    "Filter marked 100 emails as spam, 96 were actually spam" → 96% precision
  
  WHEN IT MATTERS:
    High precision = Few false alarms
    Healthcare example: "Only flag 96% true patients" (not 4% false diagnoses)
  
  TYPICAL VALUE: 98.20% (very good)

  c) RECALL
  ---------
  Formula: Recall = TP / (TP + FN)
  
  Code: recall = recall_score(y_test, y_pred, average='weighted')
  
  EXPLANATION: Of all actual "UNSTABLE" cases, how many did model catch?
  
  EXAMPLE:
    Actually UNSTABLE cases: 495 + 10 = 505 times
    Model caught: 495 times
    Recall = 495 / 505 = 98.0%
  
  INTERPRETATION: "Of all real attacks, model caught 98% of them"
  
  ANALOGY: Security system recall
    "1000 actual intruders, security caught 980" → 98% recall
    (20 attacks went unnoticed!)
  
  WHEN IT MATTERS:
    High recall = Few missed attacks
    Critical safety applications need high recall
  
  TYPICAL VALUE: 98.20%

  d) F1-SCORE
  -----------
  Formula: F1 = 2 × (Precision × Recall) / (Precision + Recall)
  
  Code: f1 = f1_score(y_test, y_pred, average='weighted')
  
  EXPLANATION: Harmonic mean of precision and recall
  
  WHY HARMONIC MEAN (not arithmetic)?
    If P=95%, R=1%: Arithmetic mean = (95+1)/2 = 48%
                    Harmonic mean = 2×95×1/(95+1) ≈ 2%
    Harmonic mean punishes imbalance more severely ✓
  
  INTERPRE: Balanced measure combining both precision and recall
  
  TYPICAL VALUE: 98.20%

  e) CONFUSION MATRIX
  -------------------
  Code: confusion_matrix = confusion_matrix(y_test, y_pred)
  
  OUTPUT (2×2 matrix):
           Predicted
           0       1
      0 [  TN     FP  ]  Actual
      1 [  FN     TP  ]
      
  EXAMPLE:
           Predicted
           0       1
      0 [ 475      20 ]
      1 [  10     495 ]
  
  VISUALIZATION:
    ● Diagonal (TN + TP) = correct predictions (green)
    ● Off-diagonal (FP + FN) = incorrect predictions (red)

STEP 3: PRINT RESULTS

  print(f"{model_name} Evaluation Results:")
  print(f"Accuracy:  {accuracy:.4f}")
  print(f"Precision: {precision:.4f}")
  print(f"Recall:    {recall:.4f}")
  print(f"F1 Score:  {f1:.4f}")

PART 7: MATHEMATICAL FOUNDATIONS
================================================================================

LOGISTIC REGRESSION FORMULA
=============================

LINEAR MODEL:
  z = w·X + b
  
  where:
    w = weight vector [w₁, w₂, ..., w₁₃]
    X = feature vector [x₁, x₂, ..., x₁₃]
    b = bias term
    · = dot product

SIGMOID FUNCTION (transforms linear to probability):
  σ(z) = 1 / (1 + e^(-z))
  
  Mathematically:
    σ(z) = e^z / (1 + e^z)
    
  Properties:
    • Output range: (0, 1) – valid probability ✓
    • σ(0) = 0.5 – middle point
    • σ(+∞) ≈ 1.0 – maximum
    • σ(-∞) ≈ 0.0 – minimum

SIGMOID GRAPH:
  P(y=1|x)
      1.0 ├─────────────────────────
          │            ╱╱╱
          │       ╱╱╱╱╱
      0.5 ├─╱╱╱╱╱
          │╱
          └────────────────────────── z
         -4   -2    0    2    4

DECISION BOUNDARY:
  If σ(z) > 0.5 → predict class 1 (UNSTABLE)
  If σ(z) ≤ 0.5 → predict class 0 (STABLE)
  
  Equivalently:
  If z > 0 → predict 1
  If z ≤ 0 → predict 0
  
  Equivalently:
  If w·X + b > 0 → predict 1
  If w·X + b ≤ 0 → predict 0

LOSS FUNCTION (Binary Cross-Entropy):
  L = -1/m × Σ[yᵢ·log(σᵢ) + (1-yᵢ)·log(1-σᵢ)]
  
  where:
    m = number of samples
    yᵢ = actual label (0 or 1)
    σᵢ = predicted probability
    log = natural logarithm
    Σ = summation over all samples

INTUITION:
  When y=1: L = -log(σ) 
    If σ=0.99 (confident correct): L ≈ 0.01 (small loss) ✓
    If σ=0.01 (confident wrong): L ≈ 4.6 (huge loss) ✗✗
  
  When y=0: L = -log(1-σ)
    If σ=0.01 (confident correct): L ≈ 0.01 (small loss) ✓
    If σ=0.99 (confident wrong): L ≈ 4.6 (huge loss) ✗✗

REGULARIZATION TERM (L2 penalty):
  L_total = L_loss + (λ/2m) × Σ(wⱼ²)
  
  where:
    λ = regularization strength (1/C)
    Σ(wⱼ²) = sum of squared weights
  
  Effect:
    Large weights → high penalty → discouraged
    Small weights → low penalty → preferred
    Prevents overfitting by keeping model simple

GRADIENT DESCENT OPTIMIZATION:
  w_new = w_old - α × ∇L
  
  where:
    α = learning rate (typically 0.01-0.1)
    ∇L = gradient (slope of loss)
  
  INTERPRETATION:
    Move weights in direction of steepest descent
    Repeat until convergence (loss doesn't decrease)

CONVERGENCE:
  Typically: 50-200 iterations
  Our setting: max_iter=1000 (safe upper bound)

LOGISTIC REGRESSION PREDICTIONS:
=================================

For each test sample, LR outputs probability:
  P(UNSTABLE | features) ∈ [0.0, 1.0]

DECISION THRESHOLD: 0.5 (default)
  If P > 0.5 → predict UNSTABLE (class 1)
  If P ≤ 0.5 → predict STABLE (class 0)

THRESHOLD ADJUSTMENT FOR SCENARIOS:
===================================

Scenario 1: GRID STABILITY PREDICTION
──────────────────────────────────────
Goal: Minimize false positives (don't alarm without reason)

Recommended threshold: 0.6
  • Predict UNSTABLE only if P > 0.6
  • More conservative
  • Costs of false alarm > cost of risk
  • Example: "Alert grid operator" (expensive)

Scenario 2: INTRUSION DETECTION
─────────────────────────────────
Goal: Minimize false negatives (catch all attacks)

Recommended threshold: 0.4
  • Predict UNSTABLE if P > 0.4
  • More aggressive
  • Cost of missed attack >> cost of false alarm
  • Example: "Missed DoS attack → system damage"

ANALOGY: Airport Security
──────────────────────────
  High threshold (0.7): Missing dangerous person
    "Let's be lenient, only stop really suspicious people"
    → Risk: Terrorist boards flight
  
  Low threshold (0.3): Many false alarms
    "Let's be strict, stop anyone slightly suspicious"
    → Risk: Long delays, inconvenience
  
  Choose threshold based on risk tolerance!

FEATURE IMPORTANCE IN PREDICTIONS:
==================================

LR learns weights w for each feature:
  Larger |w| = more important for prediction

EXAMPLE WEIGHTS (from trained LR):
  w[voltage]           = +5.2  (HIGH importance)
  w[power_factor]      = -4.8  (HIGH importance)
  w[frequency]         = +2.1  (MEDIUM importance)
  w[ev_load_ratio]     = +3.5  (MEDIUM importance)
  w[hour_sin]          = +0.8  (LOW importance)

INTERPRETATION:
  High voltage    → UNSTABLE (w > 0, effect positive)
  Low power factor → UNSTABLE (w < 0, P_low means w × 0.6 negative effect)
  High frequency  → UNSTABLE
  High EV demand  → UNSTABLE

PART 13: QUICK REFERENCE FORMULAS
================================================================================

1. STANDARDIZATION (Feature Scaling)
    X_scaled = (X - μ) / σ
    where:
      X = original feature value
      μ = mean of feature
      σ = standard deviation

2. LOGISTIC REGRESSION LINEAR MODEL
    z = w·X + b = Σ(wᵢ × xᵢ) + b

3. SIGMOID FUNCTION
    σ(z) = 1 / (1 + e^(-z))
    Range: (0, 1)

4. PREDICTION PROBABILITY
    P(y=1|X) = σ(w·X + b)

5. DECISION BOUNDARY
    If σ(w·X + b) > 0.5 → predict 1 (UNSTABLE)
    If σ(w·X + b) ≤ 0.5 → predict 0 (STABLE)

6. LOSS FUNCTION (Binary Cross-Entropy)
    L = -[y·log(σ) + (1-y)·log(1-σ)]

7. TOTAL LOSS (with L2 regularization)
    L_total = L_loss + (λ/2m) × Σ(wⱼ²)

8. GRADIENT DESCENT UPDATE
    w_new = w_old - α × ∇L
    where:
      α = learning rate
      ∇L = gradient of loss

9. ACCURACY
    Acc = (TP + TN) / (TP + TN + FP + FN)

10. PRECISION
    P = TP / (TP + FP)

11. RECALL
    R = TP / (TP + FN)

12. F1-SCORE
    F1 = 2 × (P × R) / (P + R)

13. CONFUSION MATRIX ENTRIES
    TP = True Positives (predicted 1, actual 1)
    TN = True Negatives (predicted 0, actual 0)
    FP = False Positives (predicted 1, actual 0)
    FN = False Negatives (predicted 0, actual 1)

PART 14: HYPERPARAMETER OPTIMIZATION EXPLAINED
================================================================================

WHAT ARE HYPERPARAMETERS?
==================

Parameters set BEFORE training:
  • Learning rate
  • Number of iterations
  • Regularization strength
  • Solver algorithm
  
(Different from weights w, which are learned DURING training)

HYPERPARAMETERS IN LOGISTIC REGRESSION:
========================================

1. C (Regularization Parameter)
   ───────────────────────────
   Default: 1.0
   Range: [0.001, 0.01, 0.1, 1, 10, 100]
   
   Relationship: λ = 1/C
   
   Effect:
     C=100  (λ=0.01):   Weak regularization → complex model
     C=1    (λ=1.0):    Balanced
     C=0.01 (λ=100):    Strong regularization → simple model
   
   Grid search tries all 6 values

2. penalty (Regularization Type)
   ──────────────────────────────
   Options: ['l1', 'l2']
   
   'l1' (Lasso):        Penalty = λ × Σ|wⱼ|
                        → Some weights become exactly 0
                        → Feature selection
   
   'l2' (Ridge):        Penalty = λ × Σ(wⱼ²)
                        → All weights shrink
                        → Smoother
   
   Grid search tries both

3. solver (Optimization Algorithm)
   ───────────────────────────────
   Options: ['liblinear', 'saga']
   
   'liblinear':  Traditional algorithm
                 Fast for small datasets
                 Works with 'l1' and 'l2'
   
   'saga':       Stochastic average gradient
                 Better for large datasets
                 Works with 'l1' and 'l2'
   
   Grid search tries both

4. max_iter (Maximum Iterations)
   ───────────────────────────────
   Options: [100, 500, 1000]
   
   Too low:      Model doesn't converge → worse accuracy
   Too high:     Converges early anyway, wastes time
   
   Grid search tries all 3 values

GRID SEARCH COMBINATION:
========================

Total combinations:
  6 C values × 2 penalties × 2 solvers × 3 max_iters
  = 6 × 2 × 2 × 3 = 72 combinations!

For EACH combination:
  1. Create model with these hyperparameters
  2. Run 5-fold cross-validation
  3. Record average accuracy
  4. Record parameters

Final:
  Keep hyperparameters with best average accuracy
  Example: {'C': 10, 'penalty': 'l2', 'solver': 'lbfgs', 'max_iter': 1000}
           Best CV Accuracy: 0.9825

COMPUTATION:
============
72 combinations × 5 folds × 4000 training samples = HIGH COST

Without parallelization: ~15 minutes
With parallelization (n_jobs=-1): ~3-5 minutes

OUR PROJECT:
============
We use optimize=False (default hyperparameters)
  • Fast training: ~2 seconds
  • Good enough accuracy: 98.20%
  • Sufficient for project scope

WHAT train_lr.py DOES:
  ✓ Trains Logistic Regression model on grid stability data
  ✓ Evaluates performance with multiple metrics
  ✓ Exports model for production use
  ✓ Generates interpretable decision boundaries

HOW IT WORKS:
  ✓ Loads 5000 samples, creates 14 engineered features
  ✓ Splits 80% training, 20% testing
  ✓ Trains LR using gradient descent (~2 seconds)
  ✓ Achieves 98.20% accuracy
  ✓ Exports to models/logistic_regression.pkl

KEY FORMULAS:
  ✓ Sigmoid: σ(z) = 1/(1+e^-z)
  ✓ Loss: L = -[y·log(σ) + (1-y)·log(1-σ)]
  ✓ Accuracy: (TP+TN)/(TP+TN+FP+FN)
  ✓ Precision: TP/(TP+FP)
  ✓ Recall: TP/(TP+FN)

INTERCONNECTIONS:
  ✓ train_lr.py: Standalone LR training
  ✓ train_svm.py: Standalone SVM training
  ✓ train_ids.py: Compares both on normal + attack data
  ✓ All use SAME data pipeline and features
  ✓ Results combined for ensemble voting

WHEN TO USE:
  ✓ Need fast, interpretable model → use LR
  ✓ Need complex boundaries → use SVM
  ✓ Need high confidence → use BOTH (ensemble)
  ✓ Need comparison → use train_ids.py
