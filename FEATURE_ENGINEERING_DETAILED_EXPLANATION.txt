METHOD 1: create_power_features(df)
================================================================================

PURPOSE:
--------
Creates relationships and derived metrics from fundamental power measurements.
This reveals hidden patterns in the power grid.

INPUT: DataFrame with columns [active_power, reactive_power, voltage, current, 
                                ev_demand, total_load, hour]

OUTPUT: Same DataFrame + 7 new features

DETAILED BREAKDOWN:

---[ FEATURE 1-2: POWER FACTOR & APPARENT POWER ]---

MATHEMATICS:
- Apparent Power (S): S = √(P² + Q²)
  Where: P = active power (watts), Q = reactive power (VAR)
  
- Power Factor (PF): PF = P / S = P / √(P² + Q²)

PHYSICS EXPLANATION:
- Active Power (P): Real power consumed (lights, heating, motors)
- Reactive Power (Q): Imaginary power (energy bouncing back in AC circuits)
- Apparent Power (S): Total power capacity needed
- Power Factor: Efficiency ratio (how much real work vs wasted energy)

ANALOGY: Traffic on a 4-lane highway:
- Active Power = cars actually moving (productive)
- Reactive Power = cars idling or reversing (wasteful)
- Apparent Power = total capacity needed
- Power Factor = productive cars / total capacity

CODE:
    df_feat['apparent_power'] = np.sqrt(
        df_feat['active_power']**2 + df_feat['reactive_power']**2
    )
    df_feat['power_factor'] = df_feat['active_power'] / (
        df_feat['apparent_power'] + 1e-8  # 1e-8 prevents division by zero
    )

WHY IMPORTANT:
- Power factor < 0.85 = Poor grid efficiency = Potential anomaly or attack
- Sudden drop in PF = Sign of grid instability or malicious activity

NORMAL GRID: PF ≈ 0.95-1.0 (efficient)
ATTACK GRID: PF ≈ 0.6-0.8 (inefficient)
ML MODEL LEARNS: "Low PF = anomaly flag!"


---[ FEATURE 3-4: VOLTAGE FEATURES ]---

MATHEMATICS:
- Voltage Deviation: VD = |V - 1.0|
- Voltage Squared: V² = V × V

CODE:
    df_feat['voltage_deviation'] = np.abs(df_feat['voltage'] - 1.0)
    df_feat['voltage_squared'] = df_feat['voltage'] ** 2

WHY IMPORTANT:
- Nominal voltage = 1.0 per unit (normalized)
- Deviation > 0.2 = ABNORMAL
- Voltage² captures non-linear voltage behavior

ANALOGY: Your blood pressure should be around 120/80:
- Deviation = how far from normal (5, 10, 50 points?)
- Squared term = emphasizes extreme deviations

ATTACK SIGNATURE: 
- FDI (False Data Injection) attacks often manipulate voltage readings
- Sudden spikes in voltage_deviation trigger alerts


---[ FEATURE 5: CURRENT SQUARED ]---

MATHEMATICS:
- Current²: I² = I × I

WHY:
- Power dissipation = I² × R (Joule heating)
- Captures non-linear energy losses
- High I² = overload conditions

CODE:
    df_feat['current_squared'] = df_feat['current'] ** 2

ANALOGY: Your phone charger heats up (waste heat = I² × R)
More current = exponentially more heat = potential failure


---[ FEATURE 6: EV LOAD RATIO ]---

MATHEMATICS:
- EV Load Ratio: ELR = EV_demand / (Total_Load + 1e-8)

RANGE: 0 to 1
- 0.0 = No EV charging
- 1.0 = Only EVs charging, nothing else

CODE:
    df_feat['ev_load_ratio'] = df_feat['ev_demand'] / (
        df_feat['total_load'] + 1e-8
    )

WHY IMPORTANT:
- EV charging creates sudden power demand spikes
- High ELR = Heavy EV usage = Grid stress
- Attackers might manipulate this to cause cascading failures

ANALOGY: Restaurant load:
- ELR = (number of delivery orders) / (total orders)
- High ratio = delivery system overwhelmed


---[ FEATURES 7-9: TIME-BASED FEATURES ]---

MATHEMATICS (Circular Time Encoding):
- Hour_sin: h_sin = sin(2π × hour / 24)
- Hour_cos: h_cos = cos(2π × hour / 24)
- Is_peak_hour: = 1 if 17≤hour≤21 else 0

WHY CIRCULAR:
Hour is cyclical: 23:00 → 00:00 is continuous, not a gap!
Don't want ML model to think hour 1 and hour 23 are very different when they're
actually consecutive.

Using sin/cos creates a circle:
- hour=0:  (sin=0,    cos=1)
- hour=6:  (sin=1,    cos=0)
- hour=12: (sin=0,    cos=-1)
- hour=18: (sin=-1,   cos=0)

CODE:
    df_feat['hour_sin'] = np.sin(2 * np.pi * df_feat['hour'] / 24)
    df_feat['hour_cos'] = np.cos(2 * np.pi * df_feat['hour'] / 24)
    df_feat['is_peak_hour'] = df_feat['hour'].apply(
        lambda x: 1 if 17 <= x <= 21 else 0
    )

WHY:
- Power grids have daily cycles
- Peak hours (5-9 PM) demand higher power
- Off-peak (midnight-5 AM) have lower load
- These patterns are learned by ML models

ANALOGY: Breathing as circular:
- Linear: 0→12 hours (incomplete picture)
- Circular: Full day cycle (repeats every 24 hours)
- Inhale→Exhale→Inhale (continuous)


---[ FEATURE 10: LOAD INTENSITY RATIO ]---

MATHEMATICS:
- Load Intensity Ratio: LIR = Total_Load / (Actual_Consumption_kWh + 1e-8)

CODE:
    df_feat['load_intensity_ratio'] = df_feat['total_load'] / (
        df_feat['actual_consumption_kwh'] + 1e-8
    )

WHY:
- Compares grid load against real consumption
- Detects mismatches (possible attacks or sensor faults)
- London energy dataset integration (CHANGE #2)

ANALOGY: Budget tracking:
- You plan to spend $100 (total_load prediction)
- You actually spend $85 (actual consumption)
- Ratio = 100/85 = 1.18 (spending less than planned = good)
- If ratio = 0.5, you're consuming way more than predicted = anomaly!

METHOD 2: create_statistical_features(df, window_cols=None)
================================================================================

PURPOSE:
--------
Creates statistical summaries of data TRENDS over time using rolling windows.
Captures how values CHANGE, not just their absolute values.

INPUT: DataFrame
OUTPUT: DataFrame with rolling statistics added

CONCEPT - ROLLING WINDOW:
Imagine you're watching a 3-minute "window" of video, sliding forward 1 minute
at a time:
- Minute 0-3: Stats (mean, std)
- Minute 1-4: Stats (mean, std)
- Minute 2-5: Stats (mean, std)
- ... continues

ANALOGY: Weather station:
- Each hour, calculate average temp for the last 3 hours
- Calculate variability (standard deviation) for last 3 hours
- As time passes, the "window" slides forward

FORMULAS:

1. ROLLING MEAN:
   μ(t) = (x[t] + x[t-1] + x[t-2]) / 3
   
   Smooths out noise, shows trend

2. ROLLING STANDARD DEVIATION:
   σ(t) = √[(x[t]-μ[t])² + (x[t-1]-μ[t])² + (x[t-2]-μ[t])²] / 3
   
   Shows how much values vary around the mean

3. RATE OF CHANGE (DIFFERENCE):
   Δx[t] = x[t] - x[t-1]
   
   How much did the value change from last sample?

CODE:
    for col in window_cols:
        if col in df.columns:
            # Rolling mean: average of last 3 values
            df_stat[f'{col}_rolling_mean'] = df[col].rolling(
                window=3, min_periods=1
            ).mean()
            
            # Rolling std: variability of last 3 values  
            df_stat[f'{col}_rolling_std'] = df[col].rolling(
                window=3, min_periods=1
            ).std().fillna(0)
            
            # Rate of change: difference from previous
            df_stat[f'{col}_diff'] = df[col].diff().fillna(0)

WHY THIS MATTERS:
- Stable grid: rolling_mean ≈ constant, rolling_std ≈ low
- Attacked grid: rolling_mean ≈ erratic, rolling_std ≈ high spikes

EXAMPLE TIME SERIES:
Time    Value   rolling_mean(3)  rolling_std(3)  diff
0       100     100              0               0
1       101     100.5            0.5             1
2       99      100              1               -2
3       98      99.3             1.5             -1
4       102     99.7             2.3             4

The model learns: "Sudden spikes in rolling_std = potential attack!"

METHOD 3: scale_features(X, method='standard', fit=True)
================================================================================

PURPOSE:
--------
Converts features to a common scale. Different features have different ranges:
- Voltage: 0.9 - 1.1
- Current: 100 - 5000
- Power: 1000 - 100000

ML models struggle when features have vastly different scales!

TWO METHODS:

1. STANDARD SCALING (Z-score normalization):
   X_scaled = (X - μ) / σ
   
   Where: μ = mean, σ = standard deviation
   
   Result: Mean=0, StdDev=1 (bell curve)
   
2. MIN-MAX SCALING (Normalization):
   X_scaled = (X - min) / (max - min)
   
   Result: All values between 0 and 1

ANALOGY: Height comparison:
- Raw: Person A=180cm, Person B=5'10"
  Problem: Different units!
- Scaled: Both expressed as percentile of population
  Solution: Comparable!

CODE:
    if fit:  # First time: learn scale from training data
        if method == 'standard':
            self.scaler = StandardScaler()
        else:
            self.scaler = MinMaxScaler()
        X_scaled = self.scaler.fit_transform(X)
    else:  # Later: apply learned scale to test data
        X_scaled = self.scaler.transform(X)

WHY FIT VS TRANSFORM:
- fit_transform: Learn parameters from data, then scale it
- transform: Apply previously-learned parameters to new data

CRITICAL: Never fit on test data! Only fit on training data, then transform
test data with the same scaler!

================================================================================
METHOD 5: select_features(X, y, k=10, method='f_classif')
================================================================================

PURPOSE:
--------
Feature selection: Choose the TOP k MOST IMPORTANT features.
Removes noisy/irrelevant features, improves model speed & accuracy.

TWO METHODS:

1. F-CLASSIFICATION (ANOVA):
   Tests if each feature is statistically different between classes
   
   Calculation: F = Variance_between_classes / Variance_within_classes
   
   High F = Feature is very different in stable vs unstable
            → Important feature!
   Low F = Feature is similar in both classes
           → Not useful!

2. MUTUAL INFORMATION:
   Measures how much knowing this feature reduces uncertainty about class
   
   High MI = Knowing feature X tells us a lot about class Y
   Low MI = Feature X doesn't help predict class Y

ANALOGY: Job interview features:
High F-score: Years of experience (very different between hired/rejected)
Low F-score: Shoe color (similar distribution in both groups)

CODE:
    if method == 'f_classif':
        selector = SelectKBest(f_classif, k=min(k, X.shape[1]))
    else:
        selector = SelectKBest(mutual_info_classif, k=min(k, X.shape[1]))
    
    X_selected = selector.fit_transform(X, y)

RESULT: 
- X_selected: Only top 10 (or k) most important features
- self.selected_features: Indices of chosen features

================================================================================
PART 6: KEY FORMULAS & MATHEMATICAL FOUNDATION
================================================================================

POWER & ELECTRICAL:
===================
1. Apparent Power:      S = √(P² + Q²)              [VA]
2. Power Factor:        PF = P / S                  [unitless, 0-1]
3. Voltage Deviation:   VD = |V - V_nominal|        [per unit]
4. Current-to-Power:    P = V × I × PF              [Watts]
5. Joule Heat Loss:     Loss = I² × R               [Watts]

TIME ENCODING:
==============
6. Hour to Sine:        h_sin = sin(2π × h / 24)    [cycles/hour]
7. Hour to Cosine:      h_cos = cos(2π × h / 24)    [cycles/hour]

STATISTICAL:
============
8. Rolling Mean:        μ(t) = Σ(x[i]) / n         [n=window size]
9. Rolling StdDev:      σ(t) = √(Σ(x[i]-μ)² / n)
10. Rate of Change:     Δx = x[t] - x[t-1]

SCALING:
========
11. Z-score:            X_z = (X - μ) / σ
12. Min-Max:            X_mm = (X - X_min) / (X_max - X_min)

FEATURE SELECTION:
==================
13. F-statistic:        F = Var_between / Var_within
14. Mutual Information: MI = Σ P(x,y) × log(P(x,y)/(P(x)×P(y)))

MODEL-SPECIFIC PHASE:
====================

LOGISTIC REGRESSION PHASE (train_lr.py):
─────────────────────────────────────
1. Initialize: LogisticRegression(C=1.0, ...)
2. Fit: lr.fit(X_train, y_train)
   - GOAL: Minimize log loss = -[y*log(ŷ) + (1-y)*log(1-ŷ)]
   - ALGORITHM: SGD (Stochastic Gradient Descent)
   - ITERATION: Updates weights until convergence (max_iter=1000)
   - TIME: ~2 seconds for 5000 samples
   
3. Predict: y_pred = lr.predict(X_test)
   - For each test sample, compute: P(stable) = 1/(1+e^(-w·x-b))
   - If P > 0.5: predict "stable", else "unstable"
   
4. Evaluate: accuracy, precision, recall, f1, confusion_matrix
   - RESULT: 98.20% accuracy

SVM PHASE (train_svm.py):
────────────────────────
1. Initialize: SVC(kernel='rbf', C=10, ...)
   - RBF kernel = Radial Basis Function
   - Can handle non-linear decision boundaries
   
2. Fit: svm.fit(X_train, y_train)
   - GOAL: Maximize margin (distance to decision boundary)
   - ALGORITHM: Sequential Minimal Optimization (SMO)
   - COMPUTATION: Complex (quadratic programming)
   - TIME: ~8 seconds for 5000 samples (more compute-intensive!)
   
3. Predict: y_pred = svm.predict(X_test)
   - Compute: f(x) = sign(Σ αᵢ * K(xᵢ, x) + b)
   - K = RBF kernel function
   
4. Evaluate: accuracy, precision, recall, f1, confusion_matrix
   - RESULT: 98.60% accuracy (slightly better!)

PART 9: WHY EACH FORMULA IS USED
================================================================================

POWER FACTOR (PF = P/S):
═══════════════════════
WHY:
- PF quantifies efficiency of power transfer
- PF=1.0: All power is useful (ideal)
- PF<0.85: Lots of wasted reactive power (bad)
- Attacks often cause PF to drop suddenly

ATTACK PATTERN: Normal PF=0.95 → Attack PF=0.60
ML LEARNS: "If PF drops 0.35 units in 5 minutes? FLAG AS ATTACK!"


VOLTAGE DEVIATION (VD = |V - 1.0|):
═══════════════════════════════════
WHY:
- Voltage must stay within 0.95-1.05 per unit
- Outside this = equipment damage risk
- FDI (False Data Injection) attacks manipulate voltage

ATTACK PATTERN: Injects voltage=1.5 (sensor reading, not real)
ML LEARNS: "If voltage_deviation>0.5? Sensor fraud detected!"


HOUR_SIN & HOUR_COS (Circular Encoding):
═════════════════════════════════════════
WHY:
- Hours are cyclical (23h→0h transition)
- Linear encoding: distance(hour23, hour0) = huge!
- Sin/Cos encoding: captures actual circular distance

BENEFIT:
- Allows model to learn: "Midnight patterns = similar to 11 PM"
- Better captures daily cycles


ROLLING STATISTICS:
═══════════════════
WHY:
- Stable systems: smooth rolling_mean, low rolling_std
- Attacked systems: erratic rolling_mean, high rolling_std spikes
- Temporal context: recent values matter!

EXAMPLE:
Normal grid: rolling_mean=100, rolling_std=2 (steady)
Attack grid: rolling_mean≈50→150, rolling_std=25→80 (chaotic)
ML LEARNS the difference!


SCALING (X_normalized = (X - mean) / std):
═══════════════════════════════════════════
WHY:
- Logistic Regression minimizes loss: L = -Σy*log(ŷ)
- If features have different scales, gradient descent struggles
- Feature 1 (0-1 range) vs Feature 2 (1000-100000 range)
- Gradient for Feature 2 dominates, Feature 1 ignored!

SOLUTION:
- Scale all to mean=0, std=1
- Now gradient descent updates all equally

ANALOGY: Voting weights:
- Unscaled: "10 votes vs 1,000,000 votes?" (big feature wins)
- Scaled: "Each vote counts equally" (fair)

PART 14: QUICK REFERENCE FORMULAS
================================================================================

Complete formula sheet for quick lookup:

POWER CALCULATIONS:
───────────────────
S = √(P² + Q²)                              [Apparent Power]
PF = P / S                                  [Power Factor]
P(kW) = V × I × PF / 1000                   [Active Power]
Q(kVAR) = P × √(1-PF²) / 1                  [Reactive Power]

VOLTAGE & CURRENT:
──────────────────
V_dev = |V_measured - V_nominal|            [Voltage Deviation]
I² = I × I                                  [Current Squared]

EV CHARGING:
────────────
ELR = EV_demand / Total_load                [EV Load Ratio]
LIR = Total_load / Actual_consumption       [Load Intensity Ratio]

CIRCULAR TIME:
──────────────
h_sin = sin(2π × h / 24)                    [Hour to Sine]
h_cos = cos(2π × h / 24)                    [Hour to Cosine]
peak_flag = 1 if 17≤h≤21 else 0             [Peak Hour Flag]

ROLLING STATISTICS:
───────────────────
μ(rolling) = Σ(x[i]) / window_size         [Rolling Mean]
σ(rolling) = √(Σ(x[i]-μ)² / window_size)   [Rolling Std Dev]
Δx = x[t] - x[t-1]                          [Rate of Change]

SCALING & NORMALIZATION:
────────────────────────
X_std = (X - μ) / σ                         [Standardization]
X_mm = (X - X_min) / (X_max - X_min)        [Min-Max Norm]
X_log = log(X + 1)                          [Log Transform]

LABEL ENCODING:
───────────────
'stable' → 0                                 [Binary Encoding]
'unstable' → 1
'attack' → 2 (if multi-class)

EVALUATION METRICS:
───────────────────
Accuracy = (TP + TN) / (TP+TN+FP+FN)        [Overall Correctness]
Precision = TP / (TP + FP)                  [True Positive Rate]
Recall = TP / (TP + FN)                     [Attack Detection Rate]
F1 = 2 × (Precision × Recall)/(P+R)         [Harmonic Mean]
AUC = Area Under ROC Curve                  [Overall Model Performance]
