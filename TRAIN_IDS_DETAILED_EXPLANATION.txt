STEP 7: TRAIN LOGISTIC REGRESSION MODEL
════════════════════════════════════════════════════════════════════

PARAMETERS:

WHAT HAPPENS DURING fit():
────────────────────────────

ALGORITHM: Stochastic Gradient Descent (SGD)
GOAL: Minimize logistic loss

LOSS FUNCTION (for binary classification):
L = -[y * log(ŷ) + (1-y) * log(1-ŷ)]

Where:
- y = actual label (0 or 1)
- ŷ = predicted probability

MATHEMATICS OF LOGISTIC REGRESSION:

P(class=1|X) = 1 / (1 + e^(-w·X-b))

Where:
- w = weight vector (learned during training)
- b = bias term (learned during training)
- X = input features
- e = Euler's number (2.718...)

GRAPHICAL INTERPRETATION:
                 ┌─────────────
              ╱╱    ← Decision boundary at P=0.5
           ╱╱
        ╱╱
     ╱╱
    └───────────────────────
    0          1 (X-axis: feature space)

TRAINING ITERATION (simplified):
─────────────────────────────────

Iteration 1:
- Random weights w = [0.1, 0.2, 0.15, ...]
- Compute predictions: ŷ = sigmoid(w·X_train)
- Compute loss: L = -mean(y*log(ŷ) + (1-y)*log(1-ŷ))
- Result: Loss = 0.45

Iteration 2:
- Update weights: w_new = w_old - α∇L
  (α = learning rate, ∇L = gradient)
- Compute loss: L = 0.42 (reduced!)

Iteration 3:
- w_new = w_old - α∇L
- Loss = 0.39 → Keep improving!

...continues until convergence or max_iter=1000...

Final weights are the model! These are stored in lr_model.coef_ and lr_model.intercept_

ANALOGY: Climbing a mountain in fog
- Start at random position (random weights)
- Can only see 10 meters ahead (gradient)
- Walk downhill (minimize loss)
- Keep walking until reaching valley (convergence)
- Position in valley = final weights

TIME COMPLEXITY:
- For 4000 training samples: ~2 seconds
- For 5000 test samples: ~0.1 seconds prediction


lr_pred = lr_model.predict(X_test_scaled)

PREDICTION ON TEST DATA:
────────────────────────
For each test sample:
1. Compute: ŷ = 1 / (1 + e^(-w·x-b))
2. If ŷ > 0.5: predict class 1
   else: predict class 0

EXAMPLE:
Test sample 1: X_test_scaled[0] = [0.2, -1.5, 0.8, ...]
  Step 1: ŷ = sigmoid(w·[0.2, -1.5, 0.8, ...]) = 0.78
  Step 2: 0.78 > 0.5 → predict class 1 (stable/attack detected)

Test sample 2: X_test_scaled[1] = [-0.5, 0.3, -0.2, ...]
  Step 1: ŷ = sigmoid(w·[-0.5, 0.3, -0.2, ...]) = 0.22
  Step 2: 0.22 < 0.5 → predict class 0 (unstable/no attack)

RESULT: lr_pred = [1, 0, 1, 1, 0, 0, 1, ...]  ← 1000 predictions

STEP 8: EVALUATE LOGISTIC REGRESSION
════════════════════════════════════════════════════════════════════

METRICS COMPUTATION:

1. ACCURACY = (TP + TN) / (TP + TN + FP + FN)

Where:
- TP (True Positive):  Predicted 1, Actually 1 ✓ Correct
- TN (True Negative):  Predicted 0, Actually 0 ✓ Correct
- FP (False Positive): Predicted 1, Actually 0 ✗ Wrong
- FN (False Negative): Predicted 0, Actually 1 ✗ Wrong

EXAMPLE:
If LR predicts: [0, 1, 1, 0, 1, 1, ...]
Actual labels:  [0, 1, 0, 0, 1, 0, ...]
Matches:        [✓, ✓, ✗, ✓, ✓, ✗, ...]

On 1000 test samples:
- TP = 300, TN = 660, FP = 15, FN = 25
- Accuracy = (300+660)/(300+660+15+25) = 960/1000 = 0.96 = 96%

NORMAL DATA: LR Accuracy = 98.20%
ATTACK DATA: LR Accuracy = 98.60%


2. PRECISION = TP / (TP + FP)
   "Of all positive predictions, how many were correct?"
   
   High precision = Few false alarms


3. RECALL = TP / (TP + FN)
   "Of all actual positives, how many did we catch?"
   
   High recall = Caught most attacks


4. F1-SCORE = 2 × (Precision × Recall) / (Precision + Recall)
   "Harmonic mean of precision and recall"
   
   Balances both metrics


5. CONFUSION MATRIX:
   
   Predicted:    0      1
   Actual 0:   [TN]   [FP]
   Actual 1:   [FN]   [TP]
   
   Visualization:
   [[660,  15]
    [ 25, 300]]
   
   Interpretation:
   - 660: Correctly predicted "stable/normal"
   - 15:  Incorrectly predicted "stable" when actually "unstable/attack"
   - 25:  Incorrectly predicted "unstable/attack" when actually "stable"
   - 300: Correctly predicted "unstable/attack"

WHY SVM?
────────
LR creates LINEAR decision boundaries.
SVM can create NON-LINEAR boundaries (more flexible).

EXAMPLE:
If data looks like concentric circles:
  
  LR boundary:    SVM boundary (RBF):
  ┌─────────┐     ⭕⭕⭕⭕⭕
  │ ××××××oo
  │ ××××××oo       × = class 0
  │ ××××××oo       o = class 1
  └─────────┘

SVM is much better for complex patterns!


MATHEMATICS OF SVM:
───────────────────

Goal: Find decision boundary that MAXIMIZES MARGIN (distance to nearest points)

MARGIN = Minimum distance from boundary to any training point

Maximize margin = Robust model (less affected by small noise)

CONSTRAINT (for linearly separable):
y_i * (w·x_i + b) ≥ 1  for all samples

OBJECTIVE:
Minimize: ||w||² / 2  (minimize complexity)
Subject to: y_i * (w·x_i + b) ≥ 1

OPTIMIZATION ALGORITHM: Sequential Minimal Optimization (SMO)

RBF KERNEL:
───────────
Instead of linear decision boundary:
  f(x) = w·x + b

Use RBF:
  f(x) = Σ αᵢ * K(x_i, x) + b
  
  Where K(x_i, x) = exp(-γ || x_i - x ||²)
        γ = kernel coefficient

This allows curved decision boundaries!

TRAINING TIME: ~8 seconds (more complex than LR)

ANALOGY: Separating fruit by ripeness
- LR: Draws straight line (unripe/ripe)
- SVM: Draws curved line following actual fruit distribution


svm_pred = svm_model.predict(X_test_scaled)

PREDICTION WITH SVM:
────────────────────
For each test sample x:
1. Compute: f(x) = Σ αᵢ * K(x_i, x) + b
2. Sign[ f(x) ] = prediction (1 if f(x)>0, else 0)

Result: svm_pred = [0, 1, 1, 0, 1, 0, ...]  ← 1000 predictions

================================================================================
PART 6: KEY FORMULAS & MATHEMATICAL FOUNDATIONS
================================================================================

LOGISTIC REGRESSION FORMULAS:
═════════════════════════════

1. LINEAR COMBINATION:
   z = w·x + b = Σ(w_i × x_i) + b

2. SIGMOID FUNCTION:
   σ(z) = 1 / (1 + e^(-z))
   
   Range: (0, 1)
   At z=0: σ(0) = 0.5 (decision boundary)
   At z→∞: σ(z)→1.0
   At z→-∞: σ(z)→0.0

3. PREDICTION:
   P(y=1|x) = σ(w·x + b)

4. BINARY CLASSIFICATION:
   ŷ = 1 if P(y=1|x) > 0.5  else 0

5. LOG LOSS (Cross-Entropy):
   L = -[y×log(ŷ) + (1-y)×log(1-ŷ)]
   
   Minimized during training

6. BATCH GRADIENT DESCENT:
   w_new = w_old - α × (∂L/∂w)
   
   Where α = learning rate


SUPPORT VECTOR MACHINE FORMULAS:
═════════════════════════════════

1. LINEAR DECISION BOUNDARY:
   f(x) = w·x + b

2. MARGIN:
   margin = 2 / ||w||
   
   Maximize margin = maximize robustness

3. RBF KERNEL:
   K(x_i, x_j) = exp(-γ ||x_i - x_j||²)
   
   γ = kernel coefficient (controls width)
   Low γ: considers far points (wider influence)
   High γ: considers near points only (narrow influence)

4. PREDICTION WITH KERNEL:
   f(x) = Σ α_i × y_i × K(x_i, x) + b
   
   ŷ = sign[f(x)]  (1 if f>0, else 0)


EVALUATION METRICS FORMULAS:
════════════════════════════

1. ACCURACY:
   A = (TP + TN) / (TP + TN + FP + FN)

2. PRECISION:
   P = TP / (TP + FP)
   
   "Of positive predictions, how many correct?"

3. RECALL (Sensitivity):
   R = TP / (TP + FN)
   
   "Of actual positives, how many caught?"

4. F1-SCORE:
   F1 = 2 × (P × R) / (P + R)

5. SPECIFICITY:
   Sp = TN / (TN + FP)
   
   "Of actual negatives, how many correct?"


STRATIFICATION FORMULA:
════════════════════════

For dataset with class distribution [p₀, p₁]:
- If p₀=0.6 (60%), p₁=0.4 (40%)
- Then train split maintains: [0.6, 0.4]
- And test split maintains: [0.6, 0.4]

Without stratification, random split might give:
- Train: [0.55, 0.45]  ← Wrong!
- Test: [0.70, 0.30]   ← Wrong!

PART 7: ATTACK TYPES EXPLAINED
================================================================================

CYBER-ATTACKS ON SMART GRID:
════════════════════════════

1. FALSE DATA INJECTION (FDI)
──────────────────────────────

WHAT:
- Attacker hacks into sensor/communication
- Injects fake measurements into system

EXAMPLES:
- Voltage sensor shows 1.5 V (actually 1.0 V)
- Current sensor shows 5000 A (actually 120 A)
- Frequency sensor shows 62 Hz (actually 59.95 Hz)

EFFECT:
- System makes wrong decisions based on fake data
- Grid operates incorrectly
- Can cause blackouts or equipment damage

FEATURE SIGNATURE:
- voltage_deviation > 0.5 (huge spike)
- power_factor drops to 0.4 (efficiency drops)
- Voltage/current don't match (inconsistent)

ML DETECTION:
- LR learns: "Abnormal voltage + power factor = FDI"
- SVM learns: Curved decision boundary for FDI cluster


2. REPLAY ATTACK
─────────────────

WHAT:
- Attacker captures old legitimate messages
- Replays them at wrong time

EXAMPLES:
- Captures "Normal grid state at 3 PM"
- Replays it at 6 PM (peak hours)
- System thinks grid is fine, but it's overloaded!

EFFECT:
- Delayed response to real problems
- Can miss cascading failures
- Causes instability

FEATURE SIGNATURE:
- Values repeat periodically (duplicated patterns)
- Timing doesn't match actual load
- Mismatch between predicted and actual consumption

ML DETECTION:
- LR learns: "Repeated patterns = replay"
- SVM learns: Detects temporal inconsistencies


3. DENIAL OF SERVICE (DoS)
──────────────────────────

WHAT:
- Attacker floods grid with fake requests
- Overwhelms grid infrastructure
- Grid can't respond to legitimate requests

EXAMPLES:
- Inject 10,000 EV charging requests simultaneously
- Demand suddenly jumps from 100 kW to 50,000 kW
- Grid protection systems trigger (blackout!)

EFFECT:
- Complete loss of service
- Cascading failures across grid
- Extended outages

FEATURE SIGNATURE:
- EV demand spikes to unrealistic levels
- Current oscillates erratically
- Power factor crashes

ML DETECTION:
- LR learns: "Extreme demand spikes = DoS"
- SVM learns: Detects magnitude anomalies


4. UNAUTHORIZED ACCESS
──────────────────────

WHAT:
- Attacker gains control of EV charging system
- Makes unauthorized commands
- Charges vehicles without payment/permission

EXAMPLES:
- Enables charging without authentication
- Sets unrealistic charge rates
- Accesses customer billing data

EFFECT:
- Economic loss (electricity theft)
- Privacy breach (customer data leak)
- Business disruption

FEATURE SIGNATURE:
- Unusual access patterns
- Requests from unknown sources
- Time-of-day anomalies

ML DETECTION:
- LR learns: "Unusual access pattern = unauthorized"
- SVM learns: Detects deviation from normal behavior

PART 8: WHY BOTH LR & SVM?
================================================================================

COMPLEMENTARY STRENGTHS:
════════════════════════

LOGISTIC REGRESSION:
─────────────────────
✓ FAST: 2 seconds per model
✓ INTERPRETABLE: Can see which features matter (weights)
✓ PROBABILISTIC: Returns confidence (0.0-1.0)
✓ SIMPLE: Few parameters to tune
✗ LINEAR ONLY: Can't handle curved patterns
✗ LESS ACCURATE: 98.20% vs SVM's 98.60%

USE CASE:
- Real-time prediction (low latency)
- Need to explain decisions
- When speed > precision

SUPPORT VECTOR MACHINE (RBF):
──────────────────────────────
✓ ACCURATE: 98.60% (best accuracy)
✓ NON-LINEAR: Handles complex patterns
✓ ROBUST: Works well with many features
✓ HANDLES IMBALANCE: Built-in class weight balancing
✗ SLOW: 3 seconds to train
✗ BLACK BOX: Hard to interpret
✗ NOT PROBABILISTIC: Only yes/no prediction

USE CASE:
- Maximum accuracy needed
- Complex attack patterns
- When precision > speed

ENSEMBLE: BOTH MODELS ✓
───────────────────────
Use LR output as confidence score
Compare with SVM output
If both agree: HIGH confidence
If they disagree: LOW confidence → Manual review

- Precision: 495 / (495+5) = 0.99 = 99%
           (of predicted attacks, 99% correct)
- Recall: 495 / (495+5) = 0.99 = 99%
         (of actual attacks, caught 99%)
- Specificity: 495 / (495+5) = 0.99 = 99%
              (of actual normal, correctly identified 99%)


BUSINESS INTERPRETATION:
════════════════════════

SECURITY MANAGER PERSPECTIVE:
- "Of 500 attacks, we caught 495" ← Recall = 99%
- "Of 500 normal operations, only 5 false alarms" ← Specificity = 99%
- "When we raise an alarm, it's correct 99% of the time" ← Precision = 99%

TRADE-OFFS:

High Detection (High Recall):
- Pros: Catch all attacks
- Cons: Many false alarms (security team exhausted)

High Precision:
- Pros: Few false alarms (team trusts alerts)
- Cons: Miss some attacks (security gap)

BALANCED APPROACH (IDS Goal):
- F1-Score balances precision & recall
- Want both: catch attacks AND avoid false alarms
- train_ids.py achieves 98.6% accuracy = good balance

PART 13: QUICK REFERENCE - FORMULA SHEET
================================================================================

LOGISTIC REGRESSION:
════════════════════
Sigmoid:              σ(z) = 1 / (1 + e^(-z))
Prediction:           P(y=1|x) = σ(w·x + b)
Decision:             ŷ = 1 if P > 0.5 else 0
Log Loss:             L = -[y·log(ŷ) + (1-y)·log(1-ŷ)]
Update:               w ← w - α·(∂L/∂w)


SUPPORT VECTOR MACHINE (RBF):
══════════════════════════════
Decision Function:    f(x) = Σ α_i·y_i·K(x_i, x) + b
RBF Kernel:           K(x_i, x) = exp(-γ·||x_i - x||²)
Prediction:           ŷ = sign[f(x)]
Margin:               margin = 2 / ||w||


EVALUATION METRICS:
═══════════════════
Accuracy:             A = (TP + TN) / (TP + TN + FP + FN)
Precision:            P = TP / (TP + FP)
Recall:               R = TP / (TP + FN)
F1-Score:             F1 = 2·P·R / (P + R)
Specificity:          Sp = TN / (TN + FP)


PREPROCESSING:
════════════════
Train-Test Split:     train_size + test_size = n_samples
Stratification:       class_distribution(train) ≈ class_distribution(test)
Standard Scaling:     X_scaled = (X - μ) / σ

PART 14: COMMON ISSUES & SOLUTIONS
================================================================================

ISSUE 1: Models Trained But Accuracy is Low (< 90%)
═════════════════════════════════════════════════════

LIKELY CAUSES:
- Features not scaled (StandardScaler not applied)
- Imbalanced data (e.g., 99% normal, 1% attack)
- Wrong label column identified
- Data contains too many NaN values

SOLUTION:
- Always scale features before training
- Check class distribution: print(df[label_col].value_counts())
- Verify label column: print(df.columns)
- Fill NaN values in preprocessing


ISSUE 2: SVM Very Slow (Takes > 10 seconds)
═════════════════════════════════════════════

LIKELY CAUSES:
- RBF kernel is naturally slower than LR
- Too many support vectors
- Data not scaled (kernel computation harder)

SOLUTION:
- Expected behavior! SVM is slower.
- Reduce data size for testing
- Use smaller test subset
- Or switch to LR if speed critical


ISSUE 3: Predictions All the Same (All 0 or All 1)
═════════════════════════════════════════════════════

LIKELY CAUSES:
- Model didn't train (weights not learned)
- Imbalanced data (model defaulted to majority class)
- Feature scaling problem

SOLUTION:
- Check model.coef_ to see if weights changed
- Check class distribution
- Verify scaling applied correctly
- Increase training iterations (max_iter=1000)


ISSUE 4: Confusion Matrix Shows Perfect Results (Unrealistic)
═══════════════════════════════════════════════════════════════

LIKELY CAUSES:
- Overfitting (model memorized training data)
- Data leakage (used test data in training)
- Same data used for train and test

SOLUTION:
- Always use stratified train_test_split
- NEVER fit scaler on test data
- NEVER edit data after split
- Verify X_train ≠ X_test

WHAT train_ids.py DOES:
═════════════════════════

1. LOADS GRID DATA (normal or attack)
2. PREPROCESSES & SCALES features
3. TRAINS 2 ML MODELS on the data:
   - Logistic Regression (98.2%-98.6% accuracy)
   - Support Vector Machine (98.6% accuracy)
4. EVALUATES performance (accuracy/precision/recall/f1)
5. EXPORTS models for Simulink integration
6. GENERATES visualizations comparing results

MODELS LEARN PATTERNS:
═══════════════════════

NORMAL DATA:
- What stable grid looks like
- How voltage, current, frequency should behave
- Time-based patterns (peak vs off-peak loading)

ATTACK DATA:
- False Data Injection (voltage spikes)
- Replay Attacks (repeated old patterns)
- DoS Attacks (extreme demand sudden spikes)
- Unauthorized Access (unusual access patterns)

LR ALGORITHM:
══════════════
✓ Fast (2s)
✓ Interpretable
✓ Probabilistic
✗ Linear only
→ Use for real-time prediction

SVM ALGORITHM:
────────────────
✓ Accurate (98.6%)
✓ Non-linear (RBF kernel)
✓ Robust
✗ Slow (3s)
✗ Less interpretable
→ Use for maximum accuracy

EVALUATION APPROACH:
════════════════════
1. Split data: 80% train, 20% test
2. Maintain class distribution: stratification
3. Scale features: StandardScaler (mean=0, std=1)
4. Fit models only on training data
5. Evaluate on unseen test data
6. Report: accuracy, precision, recall, f1

EXPORT FOR PRODUCTION:
═══════════════════════
- joblib.dump() saves model weights
- feature_columns.txt defines input format
- predictions.csv for verification
- Simulink loads models and predicts real-time
