MATHEMATICS OF SVM:
====================

Basic Decision Function:
    f(x) = sign(Σ α_i * y_i * K(x_i, x) + b)
    
    Where:
        α_i = Lagrange multipliers (learned)
        y_i = Training labels
        K(x_i, x) = Kernel function
        b = Bias term

Optimization Problem (PRIMAL):
    minimize: (1/2)||w||² + C * Σ ξ_i
    
    subject to: y_i(w·φ(x_i) + b) ≥ 1 - ξ_i
               ξ_i ≥ 0
    
    Where:
        ||w|| = Weight vector magnitude (margin)
        C = Regularization parameter (default=1.0)
        ξ_i = Slack variables (allow violations)

Interpretation:
    - Maximize margin: 2/||w|| (distance between classes)
    - Minimize violations: C * Σ ξ_i (misclassifications)
    - Trade-off: C controls this balance

KERNELS - THE MAGIC OF SVM:
============================

Linear Kernel:
    K(x_i, x_j) = x_i · x_j
    
    Decision boundary: Straight line/plane
    Speed: ⚡ Fast
    Use case: Linearly separable data
    Example: Predict if email is spam based on word count

RBF (Radial Basis Function) Kernel - OUR CHOICE:
    K(x_i, x_j) = exp(-γ ||x_i - x_j||²)
    
    where γ (gamma) = 1/(2σ²)
    
    Decision boundary: Non-linear curves
    Speed: ⚡⚡ Slower than linear
    Use case: Complex patterns
    Example: Detect attacks with non-linear patterns
    
    Geometrically:
        - Transforms data to higher dimension
        - Finds linear boundary in new space
        - Brings back non-linear boundary to original space
    
    Analogy: 2D planet with scattered points
             RBF kernel "inflates" space vertically
             Makes points separable by a plane
             Projects back to 2D → curved boundary

Polynomial Kernel:
    K(x_i, x_j) = (x_i · x_j + 1)^d
    
    where d = degree (2, 3, 4, ...)
    
    Decision boundary: Polynomial curves
    Speed: ⚡⚡⚡ Slowest
    Use case: Medium-complexity patterns

HYPERPARAMETER EXPLANATION:
============================

C = 1.0 (REGULARIZATION STRENGTH)
    
    Range: 0.0001 → 100+
    
    Low C (e.g., 0.1):
        - Larger margin
        - More misclassifications tolerated
        - Smoother decision boundary
        - Underfitting risk
        - Simple model
        
    High C (e.g., 100):
        - Smaller margin
        - Fewer misclassifications tolerated
        - Complex decision boundary
        - Overfitting risk
        - Tight fitting to training data
    
    Analogy: Traffic law enforcement
             C=0.1: "Don't enforce speed limit too strictly"
             C=100: "Enforce speed limit rigidly"
    
    Our choice: C=1.0 → Balanced trade-off ✓

gamma = 'scale' (RBF KERNEL COEFFICIENT)
    
    Formula: γ = 1 / (n_features * X.var())
    
    Range: Very small (0.001) → Large (1.0+)
    
    Low γ (e.g., 0.001):
        - Each training point has FAR influence
        - Decision boundary is smooth
        - Underfitting
        
    High γ (e.g., 1.0):
        - Each training point has NEAR influence
        - Decision boundary is wiggly/complex
        - Overfitting
    
    Analogy: Sound speaker
             γ=0.001: Sound travels far (smooth)
             γ=1.0: Sound is localized (sharp)
    
    Our choice: gamma='scale' → Auto-calculated ✓

random_state = 42 (REPRODUCIBILITY)
    
    Purpose: Get identical results every time
    Ensures fair comparison with LR model

probability = True (CONFIDENCE SCORES)
    
    Purpose: Enable predict_proba() method
    Returns probabilities instead of just class label
    
    Example:
        predict(X) → [1, 0, 1, 1, 0]  (class labels)
        predict_proba(X) → [[0.2, 0.8], [0.9, 0.1], ...]
                           (probability for each class)
    
    Probability interpretation:
        [0.2, 0.8] = 20% stable, 80% unstable (confident!)
        [0.51, 0.49] = 51% stable, 49% unstable (very uncertain)

TRAINING PROCESS (Sequential Minimal Optimization - SMO):
==========================================================

Algorithm: SMO (efficient inner loop)

Step 1: Initialize α_i = 0 for all training points

Step 2: Repeat until convergence:
    
    a) Select 2 Lagrange multipliers (α_i, α_j) that violate KKT conditions
    
    b) Update these 2 multipliers analytically
    
    c) Update bias term b
    
    d) Check KKT conditions: Is solution optimal?
       If yes → converge
       If no → repeat

Step 3: Extract support vectors (α_i ≠ 0)
    
    Only support vectors matter for predictions!
    Typical: ~30-40% of training data are support vectors
    
    Example: 4000 training samples → ~1200 support vectors stored

Elapsed time: ~3 seconds on modern CPU

Output:
    svm = Trained SVC model
    
    Internal state:
        - 1200 support vectors (depends on data)
        - 1200 α values (weights for each SV)
        - 1 bias term b
        - Kernel parameters (C=1.0, γ=scale, kernel=rbf)

PART 3: KERNELS IN DETAIL - THE MATHEMATICS

LINEAR KERNEL REVISITED:
=========================

Formula: K(x_i, x_j) = x_i · x_j (dot product)

Example calculation (2-D data):
    x_i = [1.5, 2.0]
    x_j = [1.0, 2.5]
    
    K(x_i, x_j) = (1.5)(1.0) + (2.0)(2.5)
               = 1.5 + 5.0
               = 6.5

Geometric interpretation:
    - Measures similarity as projection length
    - Similar points → high kernel value
    - Orthogonal points → zero kernel value

When to use:
    - Linearly separable data (like clean measurements)
    - Fast predictions needed
    - Interpretability priority


RBF KERNEL DEEP DIVE:
======================

Formula: K(x_i, x_j) = exp(-γ ||x_i - x_j||²)

where:
    γ (gamma) = kernel coefficient
    ||x_i - x_j|| = Euclidean distance

Step-by-step calculation with γ = 0.1, 13 features:

    x_i = [1.2, 0.8, 2.1, -0.5, ..., 1.5]  (13 features)
    x_j = [1.1, 0.9, 2.0, -0.4, ..., 1.6]  (13 features)
    
    Step 1: Calculate distance
        (1.2-1.1)² = 0.0001
        (0.8-0.9)² = 0.0001
        (2.1-2.0)² = 0.0001
        ... (13 terms total)
        
        ||x_i - x_j||² ≈ 0.0013
    
    Step 2: Apply exponential
        K(x_i, x_j) = exp(-0.1 × 0.0013)
                    = exp(-0.00013)
                    ≈ 0.9998 (very similar!)
    
    Another pair, larger distance:
        ||x_i - x_j||² ≈ 25 (far apart)
        K(x_i, x_j) = exp(-0.1 × 25)
                    = exp(-2.5)
                    ≈ 0.082 (quite different)

Geometric interpretation:
    - RBF = "Gaussian bump" at each training point
    - Similar points → high kernel value (close to 1)
    - Different points → low kernel value (close to 0)
    
    High-dimensional view:
        RBF implicitly maps to INFINITE dimensions!
        Each point becomes a Gaussian bump
        Linear separator in infinite space
        Projects back to original space as curved boundary


POLYNOMIAL KERNEL:
====================

Formula: K(x_i, x_j) = (x_i · x_j + c)^d

where:
    c = coef0 (usually 1)
    d = degree (2, 3, 4, ...)

Examples with c=1:

    Degree 2 (Quadratic):
        K = (dot_product + 1)²
        Example: (6.5 + 1)² = 7.5² = 56.25
    
    Degree 3 (Cubic):
        K = (dot_product + 1)³
        Example: (6.5 + 1)³ = 7.5³ = 421.875

Effect of increasing degree:
    - d=1: Linear (no polynomial)
    - d=2: Quadratic curves (parabolas)
    - d=3: Cubic curves (more complex)
    - d=4+: Very complex (overfitting risk!)

When to use:
    - Data has polynomial relationships
    - Moderate computational budget
    - Not for very high degree (expensive)

PART 4: SUPPORT VECTORS - THE CORE OF SVM
================================================================================

WHAT ARE SUPPORT VECTORS?
===========================

Definition: Training points that lie on or violate the margin

In equation form:
    α_i ≠ 0 (only these points matter!)
    
    Most training points: α_i = 0 (far from boundary)
    Support vectors: α_i > 0 (close to or crossing boundary)

Example from 4000 training samples:
    - 3200 points: α_i = 0 (interior, not needed)
    - 800 points: α_i > 0 (support vectors - these define boundary!)

Visual representation (2D):

```
    ■ ■ ■         Class 1 (stable)
    ■ ○ ■
    ■ ○   ← Support vectors (○) on margin
        ○ □
      □ □ □
      □ □        Class 0 (unstable)
      
    ○ = Support vectors (α_i ≠ 0) - only these needed!
    ■■ = Non-support points (α_i = 0) - can be removed
    □□ = Non-support points
```

MARGIN CONCEPT:
================

Definition: Distance from boundary to nearest training point

Formula: margin = 2 / ||w||

Optimization objective:
    MAXIMIZE margin (make w small)
    while allowing some misclassifications (slack ξ_i)

Trade-off controlled by C:
    - C small (0.1): Large margin, more violations tolerated
    - C large (100): Small margin, strict classification
    
    Objective: minimize [(1/2)||w||² + C·Σξ_i]
               ↑ small w        ↑ few violations


DECISION BOUNDARY DEFINED BY:
==============================

Only the support vectors matter!

Decision function:
    f(x) = sign(Σ α_i·y_i·K(x_i, x) + b)
    
    Σ sums ONLY over support vectors (where α_i ≠ 0)
    
    Non-support vectors: α_i = 0, so term drops out
    
    Efficiency:
        - Train on 4000 points
        - Store only 800 support vectors
        - Faster predictions!

Example prediction for new point x_new:
    f(x_new) = sign(
        α_1·y_1·K(SV_1, x_new) +    ← SV_1 = support vector 1
        α_2·y_2·K(SV_2, x_new) +    ← SV_2 = support vector 2
        ...
        α_800·y_800·K(SV_800, x_new) +  ← SV_800 = support vector 800
        b
    )
    
    Only 800 kernel calculations per prediction (not 4000!)

PART 5: HYPERPARAMETER TUNING WITH GRIDSEARCHCV
================================================================================

WHEN optimize=True is set:

PURPOSE:
==========

Find best hyperparameters through exhaustive search

Parameter grid:
    C         : [0.1, 1, 10, 100]
    kernel    : ['linear', 'rbf', 'poly']
    gamma     : ['scale', 'auto', 0.001, 0.01, 0.1]
    degree    : [2, 3, 4] (poly kernel only)

Total combinations: 60+ (varies by kernel)


GRIDSEARCHCV PROCESS:
=======================

High-level flow:

    1. ITERATE over parameter combinations:
       for each combination in parameter grid:
    
    2. CREATE model with these parameters:
       svm = SVC(C=0.1, kernel='linear', gamma='scale')
    
    3. RUN 5-FOLD CROSS-VALIDATION:
       for each fold (1 to 5):
           fit model on 4 folds
           evaluate on 1 fold validation
           record accuracy
       average_accuracy = mean of 5 fold accuracies
    
    4. TRACK best combination:
       if average_accuracy > best_score:
           best_params = current combination
           best_score = average_accuracy
    
    5. RETURN best model trained on ENTIRE training data


DETAILED TIMING:

Each combination:
    - 5 fold CV = 5 model trainings
    - Each training: 2-5 seconds
    - Per combination: 10-25 seconds
    
Total for 60 combinations:
    - Sequential: 60 × 15 sec = 900 sec = 15 minutes
    - With parallelization (n_jobs=-1): 60 / CPU_cores × 15 sec
    - On 8-core CPU: ~2 minutes


PARAMETER EFFECTS:

C parameter sweep [0.1 → 1 → 10 → 100]:
    CV Accuracy: [0.975, 0.976, 0.978, 0.976]
    
    Best: 0.978 at C=10
    Interpretation: C=10 better than C=1 (more strict)
                   But C=100 worse (overfitting)

Kernel sweep [linear → rbf → poly]:
    CV Accuracy: [0.972, 0.986, 0.981]
    
    Best: 0.986 with RBF kernel
    Interpretation: RBF captures non-linear patterns better
                   than linear or polynomial


COMPARISON TABLE:

Parameter Set 1: C=1.0, kernel='rbf', gamma='scale'
    5-fold CV: 0.9830
    Test accuracy: 0.9860

Parameter Set 2 (optimized): C=10, kernel='rbf', gamma=0.01
    5-fold CV: 0.9862  ← Slightly better
    Test accuracy: 0.9875  ← Slightly better

Improvement: +0.15% accuracy (from 98.60% → 98.75%)
Trade-off: +10 minutes tuning time


OUR CHOICE: optimize=False
============================

Why not tune?
    ✗ Time cost: 10-15 minutes
    ✗ Marginal improvement: ~0.2%
    ✓ Defaults work well enough (98.60% is excellent!)
    ✓ Ensures comparison fairness with LR (2 seconds training)
    ✓ Scientific rigor: pre-defined hyperparameters

INTERPRETABILITY:
===================

Logistic Regression - WHITE BOX:
    ✓ Can see weights for each feature
    ✓ Understand impact of each feature
    ✓ Example: voltage weight = 0.5 (important)
    ✓ Linear relationships easy to explain

SVM - BLACK BOX:
    ✗ Hard to explain decisions
    ✗ Support vector relationships opaque
    ✗ RBF kernel is implicit (no visible boundary equation)
    ✗ Non-linear patterns hard to interpret


PROBABILITY OUTPUT:
=====================

Logistic Regression:
    ✓ P(stable) = sigmoid(w·x + b)
    ✓ Natural probability interpretation
    ✓ Example: 0.75 = 75% confident stable
    ✓ Easy thresholding: if P > 0.5 then stable

SVM:
    ✗ Not probabilistic by default
    ✗ Returns: f(x) = +1 or -1
    ~ With probability=True: fits separate Platt model
      (post-hoc probability calibration)
    ~ Slower prediction with probabilities


USE CASE DECISION TREE:

Is data linearly separable?
    YES → Use Logistic Regression
         (faster, simpler, interpretable)
    NO → Use SVM with RBF
        (captures complex patterns)

Do you need probabilities?
    YES → Logistic Regression
    NO → SVM fine

Do you have >10k samples?
    YES → Logistic Regression (faster scaling)
    NO → Either (SVM fine for <10k)

Need interpretability?
    YES → Logistic Regression
    NO → SVM acceptable

Our choice:
    → Train BOTH (small data, benefit from SVM's power)
    → Compare results
    → Use whichever performs better

PART 10: CRITICAL THRESHOLDS FOR ATTACK DETECTION
================================================================================

DEFAULT THRESHOLD: 0.5 (50%)

For binary classification:
    If P(attack) >= 0.5 → Predict: ATTACK
    If P(attack) < 0.5 → Predict: NORMAL

But wait! SVM returns integer labels (+1, -1), not probabilities!

With probability=True enabled:
    predict_proba() returns [[P(normal), P(attack)]]
    Example: [[0.3, 0.7]] means 70% attack confidence

THRESHOLD TUNING FOR DIFFERENT SCENARIOS:
============================================

Scenario A: Grid Stability Prediction
    Goal: Minimize false alarms
    Threshold: 0.6 (conservative)
    
    If attack_prob >= 0.6:
        → Only raise alarm if very confident
        
    Trade-off:
        ✓ Fewer false alarms
        ✗ Miss some actual attacks
    
    Confusion matrix impact:
        FP ↓ (false alarms decrease)
        FN ↑ (missed attacks increase)
        
    Use case: Grid operates less frequently

Scenario B: IDS - Intrusion Detection
    Goal: Catch ALL attacks (minimize FN)
    Threshold: 0.4 (aggressive)
    
    If attack_prob >= 0.4:
        → Raise alarm even if not super confident
        
    Trade-off:
        ✓ Catch more attacks
        ✗ More false alarms
    
    Confusion matrix impact:
        FP ↑ (more false alarms)
        FN ↓ (fewer missed attacks - GOOD!)
        
    Use case: Better safe than sorry in security

                Normal  Attack

================================================================================
PART 11: FORMULA QUICK REFERENCE - ALL 15 KEY FORMULAS
================================================================================

1. EUCLIDEAN DISTANCE (for RBF kernel):
   d(x_i, x_j) = √(Σ(x_ik - x_jk)²)
   
   Example: √((1.5-1)² + (2-1.5)² + ...) = √0.5 ≈ 0.707

2. RBF KERNEL:
   K(x_i, x_j) = exp(-γ ||x_i - x_j||²)
   
   With γ = 0.1:
   K = exp(-0.1 × 0.5) = exp(-0.05) ≈ 0.951

3. SVM DECISION FUNCTION:
   f(x) = sign(Σ α_i·y_i·K(x_i, x) + b)
   
   If f(x) > 0 → Class 1 (attack)
   If f(x) < 0 → Class 0 (normal)

4. MARGIN:
   margin = 2 / ||w||
   
   Maximize margin ↔ Minimize ||w||²

5. REGULARIZED SVM OBJECTIVE:
   minimize: (1/2)||w||² + C·Σξ_i
   
   C = 1.0 (balanced)
   ξ_i = slack variables (allow violations)

6. STANDARD SCALER:
   X_scaled = (X - μ) / σ
   
   μ = mean, σ = standard deviation
   Result: X_scaled has μ=0, σ=1

7. LABEL ENCODING:
   y_encoded: 'normal' → 0, 'attack' → 1

8. LOGISTIC FUNCTION (for comparison):
   P(y=1|x) = 1 / (1 + exp(-(w·x + b)))
   
   Returns probability ∈ [0, 1]

9. SIGMOID (LR's non-linearity):
   σ(z) = 1 / (1 + e^(-z))

10. LR LOG-LOSS:
    L = -(1/m) Σ[y·log(ŷ) + (1-y)·log(1-ŷ)]
    
    m = number of samples
    y = true label, ŷ = predicted probability

11. ACCURACY:
    Accuracy = (TP + TN) / (TP + TN + FP + FN)

12. PRECISION:
    Precision = TP / (TP + FP)

13. RECALL:
    Recall = TP / (TP + FN)

14. F1-SCORE:
    F1 = 2·(Precision·Recall) / (Precision + Recall)

15. CROSS-ENTROPY (SVM equivalent):
    L_hinge = Σ max(0, 1 - y_i·f(x_i))
    
    Hinge loss: Penalizes wrong OR close predictions

================================================================================
PART 14: DEBUGGING & COMMON ISSUES
================================================================================

ISSUE 1: Model accuracy drops below 95%
    Possible causes:
        ✗ Feature engineering broken
        ✗ Data preprocessing removed important data
        ✗ Scaling not applied
        ✗ Label encoding incorrect
    
    Debug steps:
        1. Check X_train shape: should be (4000, 13)
        2. Check y_train values: should be [0, 1] only
        3. Print feature statistics: X_scaled.mean() ≈ 0
        4. Verify no NaN values: df.isnull().sum() = 0

ISSUE 2: SVM training hangs (infinite loop)
    Possible causes:
        ✗ SMO algorithm not converging
        ✗ Data has extreme outliers
        ✗ Features not scaled (RBF kernel sensitive!)
    
    Debug steps:
        1. Verify StandardScaler applied
        2. Check for extreme values: X_scaled.max() < 4?
        3. Set max_iter=5000 for patience
        4. Try different C value (0.1 to 100)

ISSUE 3: Memory error with large dataset
    Possible causes:
        ✗ SVM stores all support vectors in memory
        ✗ GridSearchCV × 5-fold CV × dataset size
    
    Solutions:
        1. Reduce dataset size to 3000 samples
        2. Set n_jobs=1 (disable parallelization)
        3. Use LinearSVC instead of SVC(kernel='rbf')
        4. Reduce GridSearchCV parameter grid

ISSUE 4: SVM slow (10+ seconds)
    Possible causes:
        ✗ RBF kernel complexity
        ✗ Large dataset (6000+ samples)
        ✗ GridSearchCV enabled
    
    Solutions:
        1. Use optimize=False (already 3s)
        2. Use kernel='linear' for faster training
        3. Reduce dataset size
        4. Use LinearSVC for >100k samples

  └─ Non-linear transformation to higher dimension

  └─ Separates classes with maximum buffer zone

  └─ Controls balance between margin size and violations
